A doc-site 404 is a high-traffic dead end (stale links, typo'd .html paths), so turn a wrong URL into a recovery moment. Material's header already provides search. The site is deployed with mike under a versioned path, so a root-relative link would 404 again -- but config.site_url is the wrong base to build one from: mike's injected plugin rewrites it on every deploying build to include the version being deployed, with no trailing slash (config.site_url + ""), so a link built as config.site_url ~ "latest/" would render as ".../boilerplate/0.3latest/" instead of ".../boilerplate/0.3/latest/". Every link below is instead built from extra.site_root, an un-versioned root mike never touches, and pinned to the "latest" alias mike maintains, using the directory-style paths the rest of the site renders. This file is also published to the gh-pages branch root (see RELEASING.md) -- GitHub Pages serves only one site-wide 404.html, and mike deploys exclusively under versioned and alias directories, never the branch root. #} {% block content %}
